- BoardButtonPanel 为首次选择语音快捷键的用户预选当前系统对应的组合键。自定义组合键可在「设置 → 蓝牙快捷键」编辑，设备页保留其值。

- The paired LAN Agent path reuses the dashboard session transport payload and expires when the Agent Bus feed stops responding. The device card renders the board ID of the verified active transport, and Wi-Fi pairing verifies the selected board before activating it.
- 设备栏和侧栏使用绑定设备的已验证连接状态。USB 优先，已配对且在线的同一台设备显示 Wi-Fi。
- Wi-Fi 下可以提交 Agent 跟随，沿用设备当前形象。形象素材仍由 USB 同步。

- The session feed uses the shared terminal predicate so silent reply cards expire on schedule.
- Other local Agents contribute recent conversation cards. Voice previous/next and auto-follow stay on the selected Agent.

Follow/appearance cancellation describes only the stopped request; it does not promise the device kept the old image. Unknown native appearance codes are replaced by a short failure notice, never a success notice or automatic resend.

USB follow and appearance changes use a read-only preflight for older unknown transfers. DeviceContext owns cancellation and continuity across board, connection generation, and boot changes.

设备栏在形象原始传输保护生效时提供「确认重启并恢复」。恢复先被动核对同一设备的新启动，随后只恢复串口连接；旧形象操作保留未知结果，不重发。

设备诊断展示当前 USB 握手声明的 WASM 运行时、画布和宿主能力，只有设备身份与诊断目标一致时才展示。

KeyboardConfiguration hosts the existing BoardButtonPanel and BluetoothShortcutPanel. Both use the P4BoardInputMap diagram and ControlGlyph. The Bluetooth panel reads and changes mode and per-gesture mappings over USB when connected, or through the authenticated Wi-Fi peer for the selected board and boot.

键盘配置顶部以「按钮配置」「蓝牙快捷键」两个标签切换，默认显示按钮配置。切换保留编辑内容，蓝牙页隐藏时暂停配置轮询并退出组合键录入。

蓝牙快捷键的示意图和映射列表可离线查看。页面只缓存设备标识和上次读取的映射。连接其它设备时仅显示与目标设备匹配的映射，蓝牙实时状态和配对码只在设备连接后显示。

配对面板保留设备列表和选择，离开其它设置时暂停轮询。按键配置按设备能力提供实体键双击，并回读实际下发结果。蓝牙模式说明和默认快捷键由键盘配置页展示。

蓝牙快捷键支持左右修饰键以及只发修饰键的空主键。录入只在当前编辑框聚焦时读取组合键，确认保存后才写入设备。旧固件继续显示其支持的按键选项。
# SW3 default compatibility

BoardButtonPanel offers an explicit, single-row restore for SW3 long-press
when its saved action differs from the default. New/missing PC configuration already defaults
to system_settings. Legacy v9 disabled values cannot prove user intent, so the
panel preserves them until the user chooses restore and synchronizes. The action
requires systemSettings capability and never triggers a device reset or automatic
write. Windows and macOS share this behavior.
